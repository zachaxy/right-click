## 实际 UI / 访达验收

1. 使用电脑操作工具查看本机超级右键 2.4.9 的设置页和工具箱，记录功能，不更改原应用配置。
2. 启动 `~/Applications/RustClick.app`。首页、中文导航、操作台和模板列表加载正常，实际检查过界面截图。
3. 使用原生目录选择面板选中 `build/acceptance`。
4. 在桌面界面新建 `RustClick 验收.md`，工具显示完成；文件系统确认文件存在。
5. 在文字工具输入中文，点击生成二维码，界面返回 `build/acceptance/二维码.png`。
6. 用户启用 **RustClick Finder** 后，PlugInKit 显示扩展为 `+`（已启用）。
7. 在访达中对独立测试文件 `readme.txt` 右键，确认 RustClick 及全部功能子菜单出现。
8. 从右键选择“文件信息与校验值”，主应用接收到所选文件和目录，并展示 30 字节、权限 644、MD5/SHA1/SHA256/SHA512。

实机发现并修复：Finder 复制菜单项时不会保留 `representedObject`。改为递增 `tag` 和扩展内请求表，并先以回归测试重现丢失参数的问题。修复后再次进行上述第 8 步，通过。

### 拷贝路径弹出操作台修复

用户反馈“拷贝路径”会跳转主控制台。原因是扩展使用默认前台启动，主应用又把全部菜单请求交给网页操作台。现改为不激活应用的 URL 投递，主应用在 Rust 后台队列直接执行拷贝路径/名称；冷启动依据 AppKit 启动通知决定是否显示窗口，拷贝失败时显示独立错误提示。

- 退出主应用后，在访达对 `readme.txt` 选择 RustClick → 文件工具 → 拷贝路径。访达保持焦点，粘贴得到完整绝对路径；确认 RustClick 已在后台启动。
- 主应用运行时，对 `RustClick 验收.md` 选择“拷贝名称”。访达保持焦点，粘贴得到 `RustClick 验收.md`，中文和空格完整；主控制台仍停留在概览页。
- 随后选择“文件信息与校验值”，操作台正常打开并显示 `readme.txt` 的 30 字节及全部校验值。
- 重新构建并安装到 `~/Applications/RustClick.app`，扩展仍为已启用状态；菜单参数、后台路由及 2 项界面回归测试通过，应用签名验证通过。


### 全部访达操作脱离主控制台

后续修复将原先网页中的菜单参数处理迁移到 `FinderActions.swift`，仅显式“打开 RustClick 操作台”保留主窗口流程。其他动作使用 Rust 引擎、原生系统能力和独立面板。原生输入/结果面板不会激活主应用；复制目录选择使用系统面板。

实际从访达菜单验证：

1. 主应用退出后选择新建 Markdown，只出现“新建文件”输入面板；提交 `右键独立窗口验收.md` 后，文件真实写入 `build/acceptance`，访达保持当前目录。
2. “文件信息与校验值”显示独立结果窗口，包含 `readme.txt` 的 30 字节、权限和四种校验值，可独立拷贝结果或定位文件；最终安装版已实测完整 SHA512 自动换行显示。
3. “复制文件到 → 其他目录”直接出现系统目录选择器；选定 `build` 后，确认 `build/readme.txt` 与原文件逐字节相同。
4. 对独立验收文件选择“永久删除”，出现独立确认框；点击取消后原文件仍存在。

上述是代表性实机验收；AirDrop、终端自动化、截图、壁纸等仍受下面列出的设备/权限验证范围限制。

### 每个功能的菜单层级配置

控制台新增“右键菜单”页面，与 Finder 共享同一份功能目录。层级通过 `menuLevels` 保存；旧配置保持原有默认位置。以 `build/acceptance/readme.txt` 实测：

1. 在控制台搜索“拷贝路径”，设为一级。下次右键直接出现“拷贝路径”，与 RustClick 同级；“文件工具”中不再重复显示。
2. 点击一级“拷贝路径”，在访达“前往文件夹”输入框粘贴，得到测试文件的完整绝对路径，访达保持前台。
3. 改为二级，下次右键显示 RustClick → 拷贝路径；“文件工具”内没有重复项。
4. 改为三级，下次右键显示 RustClick → 文件工具 → 拷贝路径。
5. 选择“默认（三级）”后，配置中的测试覆盖项清除。整个过程无需重启访达。验收后保留用户原来的层级和隐藏偏好。

实机检查了页面截图、搜索结果、层级数量、路径预览和自动保存提示。单项连续保存、恢复默认及动态项目由上述自动测试覆盖。原来的分组批量平铺入口已由下面的分组位置设置替代。

### 分组位置与子项继承

用户要求“新建文件”作为一级入口时，其子项默认位于二级，并允许子项独立提升。新增独立的 `menuGroupLevels`，不再通过批量覆盖 `menuLevels` 来设置分组。控制台提供“分组位置”和“跟随分组”；“子项跟随分组”只清除当前分组子项的位置覆盖。

1. 控制台展开“新建文件”，将分组位置选为“一级 · 子项二级”。下次访达右键显示一级“新建文件”，内部的纯文本、Markdown、Word 等为二级；配置没有写入任何新建子项覆盖值。
2. 单独将“新建 Markdown”选为一级，访达出现独立一级“新建 Markdown”；原“新建文件”内不再重复 Markdown，其他格式仍在二级。
3. 点击提升后的“新建 Markdown”，独立输入面板正确定位 `build/acceptance`；提交后真实生成 `菜单分组继承验收.md`。
4. 点击“子项跟随分组”，Markdown 恢复继承，保留“新建文件”一级入口。此前用户对拷贝路径等其他功能的设置保持原值。

新版已安装至 `~/Applications/RustClick.app`，页面显示一级分组和“跟随分组（二级）”的子项。分组变回二级、独立子项位置保留、工具栏归并、动态模板继承由原生与界面测试覆盖。

### 隐藏 Dock，仅保留菜单栏入口

主应用的 `Info.plist` 新增 `LSUIElement=true`，启动时使用 `.accessory`，不再强制切换为 `.regular`。此模式允许打开窗口而不显示 Dock 应用图标，参照 [Apple ActivationPolicy.accessory 文档](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum/accessory)。顶部图标单击保留 `show()`，右键显示“打开 RustClick／退出 RustClick”；关闭窗口仍只隐藏窗口。

- 新版编译、签名并安装成功；在本机启动控制台，访达扩展仍显示已启用。
- 通过 `NSRunningApplication` 读取实际进程的 activation policy，确认值为 `1`（accessory），同时确认安装包的 `LSUIElement` 为 true。
- 关闭控制台后再次读取进程，确认仍在运行且保持 accessory。当前 `showTray` 配置为 true。
- 电脑操作工具读取 Dock 和 SystemUIServer 超时，因此没有声称完成顶部图标左键／右键的自动点击验收。该入口使用既有窗口打开方法和原生菜单。
